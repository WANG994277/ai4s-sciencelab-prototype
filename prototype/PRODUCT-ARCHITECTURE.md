# AI4S 产品架构与导航说明

## 产品结构

```text
门户与生态层
├─ 门户首页
├─ 集团科研资源中心（未登录/登录两种状态）
├─ 场景方案
└─ 科研成果

个人科研工作层
├─ 科研工作台：组织与推进
├─ AI 科研中枢：智能执行
├─ 我的资源：授权、收藏、申请、使用与发布管理
└─ 我的课题空间：正式协作课题目录

集团科研治理层（集团门户顶导）
├─ 科研管理
│  ├─ 立项管理、过程管理、成果管理、外协管理
│  └─ 人才管理、考核管理、日程管理及各域专属智能体
└─ 科研规范
   ├─ 科研伦理、数据安全、AI 辅助科研与实验安全
   └─ 知识产权、成果发布、过程归档及规范智能体

课题问题求解层
└─ 课题空间
   ├─ 空间概览
   ├─ 关键问题
   ├─ 科研任务
   ├─ 作业监控
   └─ 空间资产

任务详情提供深度工作视图，并承载成员、讨论、方案或产出版本送审、反馈和确认；空间概览承载课题动态及当前判断摘要。当前判断和假设验证情况归关键问题，任务结果及结论归任务详情和相关报告，文件与正式科研资产归空间资产。跨任务汇总通过阶段研究总结任务完成，不设置独立的协作与评审、研究结论或研究判断一级入口。
```

## 核心责任

- 门户：平台认知、场景传播、资源发现和用户转化。
- 科研工作台：作为个人科研驾驶舱，跨课题聚合今日概览、科研活动、待办、风险与科研中枢运行状态；允许选定一个“当前关注课题”，在不切换全局工作范围的前提下查看该课题的关键动态、最近产出和下一里程碑，并提供进入课题空间的快捷路径。
- AI 科研中枢：围绕目标规划并执行科研任务，保留证据与工具调用过程。
- 集团科研资源中心：承载全集团资源发现；登录后增加权限、申请、加入课题和调用操作。
- 我的资源：第一层按“可用资源、我创建的、我的收藏、我的申请”组织，第二层按资源类型筛选；“我创建的”包含草稿和已发布资源，“我的申请”同时包含已通过和审批中的资源，并提供集团资源中心快捷入口。
- 我的课题空间：集中展示本人负责或参与的正式课题，并提供进入具体课题空间的唯一目录入口；具体课题不在全局顶部或全局侧栏逐项展开。
- 科研管理：作为集团门户一级入口，聚合七类科研管理事项；各管理智能体只提供检查、提醒和办理建议，关键审批与管理决策由责任人确认。
- 科研规范：作为集团门户一级入口，将制度、专业规范和平台操作指引转化为按科研行为场景可查询的准则；页面自身不设置独立助手。
- 平台小助手：默认位于集团门户页面右下角，支持视口内拖动、文字提问、截图/文件上传、粘贴截图与语音输入；统一回答平台导航、功能使用、权限申请和科研流程问题，与执行专业科研任务的科研中枢智能体明确分工。
- 课题空间：以关键问题为主轴，承载假设、验证标准、执行任务、证据材料、人工判断与当前答案；成果复用在问题解决后按价值和权限选择进行。科研任务是稳定的研究工作对象，可为文献、计算、联合研究或实验方案；一次科研超级中枢执行形成任务下的一条会话。任务工作区可直接新建并执行会话，任务详情提供深度工作与人工接管视图，不再设置独立的空间级中枢。

## 关键规则

1. 全局探索可以不属于课题；一旦进入持续研究，应关联或创建课题空间。
2. 课题空间决定 AI 可使用的知识、数据、模型、工具、权限和配额。
3. 任务完成不等于问题解决。AI 执行结果先作为待验证证据或过程产物，必须回到关键问题、假设和验证标准进行判断。
4. 问题解决以科研人员确认的可信答案为主要终点，答案需说明依据、适用范围和剩余不确定性。
5. 具有复用价值的结论和产物，可在复现、评审、脱敏和权限审核后整理为资产并发布到组织或集团科研资源中心；这是可选后续流程。
6. 全局科研与课题空间使用互斥导航；课题入口由工作台、科研中枢和我的资源按上下文提供。
7. “科研活动”是工作台的上位聚合概念，包含课题空间、个人研究和临时任务；“课题空间”仅承载正式、持续、多人协作的课题。
8. 登录后顶导提供工作台入口和紧凑的当前空间切换；侧栏在全局科研与具体课题间互斥。
9. 科研管理与科研规范属于集团级能力，固定在最外层门户导航中，顺序为“科研资源—科研管理—科研规范—科研社区”；不放入登录后的工作台或课题空间顶栏。
10. 外协原型中“我的科研任务、我的科研活动、我的科研资产”均按当前课题理解，在本架构中分别归入“科研任务、空间概览中的课题动态、空间资产”；个人级“我的”只出现在跨课题工作台和个人资源目录。
11. 原“深度研究台”不再占用一级导航，其“研究脉络—主工作区—AI 与证据上下文”工作界面作为任务工作视图，支持科研人员在执行和判断节点手动接管。
12. 科研工作台中同时出现个人与课题信息时，必须使用“个人跨课题／课题空间视角”显式标识；课题信息仅作为关注窗口，只有点击“进入课题空间”后才切换导航和工作边界。
13. 科研任务按待开始、运行中、待确认、已完成展示执行状态；待执行归待开始，等待人工确认才归待确认。执行状态与产出确认状态分别展示，执行完成不代表研究结论已获确认。
14. 分配给当前用户的评审事项并入工作台现有待我处理及协同事项统计和筛选，处理时回到关联课题任务。当前示例用户为林夏；协作记录与评审仅在本地演示，不发送真实通知、不改变成员权限。
# 工作台视觉试版（2026-10-01）

最新收拢：六类内容为待我处理、发起与继续研究、AI 研究建议、我的研究任务、我的课题与最近工作、最近产出。定时计划作为“我的研究任务”的一个视图管理，每次触发生成独立执行任务；当前运行出现在运行中，需要人工判断的结果进入待我处理，产出进入最近产出。协同只在需要本人行动时进入待办；一般动态进入通知中心，讨论与协作过程留在课题空间。已取消独立的定时研究区域、执行状态条和重复的课题概览。

个人工作范围保持不变，内容顺序为个人概览、研究输入、执行轨迹、AI 下一步建议与定时研究、关注课题与跨课题待办、科研活动与最近产出。AI 建议不等于已执行任务，须人工采纳；定时研究用于持续文献跟踪、实验数据检查和周报汇总，可暂停，输出需要人工确认。关注课题只是空间信息窗口，正式操作通过课题空间入口进行。所有示例数值、状态与任务行为为静态/会话级模拟。
